# ADR-0013: SOL v0.1 Design-Stage Architecture Freeze

**Status:** Accepted  
**Date:** 2026-08-20

## Context

SOL v0.1 has completed the current architecture-design cycle through ADR-0012. Independent validation identified and closed the AR-01/02/03/04 contract gaps, followed by counterexample-oriented re-review and official-document stress testing against MOOSE, COMSOL, and Ansys.

The latest design-stage validation found no remaining Architecture defect in the reviewed scope and recommended acceptance of ADR-0011 and ADR-0012. The same minimal thermal semantics can be projected to materially different backend structures without changing Core semantic meaning, while the plasma/QRC and multi-product orchestration cases remain expressible without importing backend-native vocabulary into Core.

This decision deliberately separates architecture freeze from implementation and Adapter V&V.

## Decision

### 1. Freeze scope

SOL v0.1 design-stage architecture is frozen for the normative architecture and contract decisions represented by ADR-0001 through ADR-0012, including:

- semantic Entity / Property / Relation boundaries;
- Value / ValueDefinition and unit/dimension semantic boundaries already accepted by prior ADRs;
- semantic preservation across backends;
- six-family Constraint architecture;
- inheritance/interface composition decisions in the accepted v0.1 scope;
- identity, namespace, package, and versioning contracts;
- Profile / BackendAdapter separation;
- five-field `MappingRule`;
- four-field `MappingClaim`;
- explicit `MappingPlan`;
- deterministic effect/action/lifecycle/BackendTarget contracts in ADR-0011;
- Qualified Relation Cardinality in ADR-0012.

### 2. Meaning of freeze

`Frozen` means these contracts are the design baseline for implementation work. They SHALL NOT be changed merely to simplify a backend integration or because a later Adapter has a different native object model.

A frozen contract MAY be reopened only when new evidence establishes one of the following:

```text
Architecture defect
normative contradiction
independent-validator nondeterminism
cross-backend semantic counterexample
reference-model impossibility not attributable to Profile/Adapter/backend limitation
```

Implementation convenience alone is not sufficient evidence.

### 3. Explicitly not required for this freeze

The following are not prerequisites for the design-stage architecture freeze:

- installing MOOSE, COMSOL, or Ansys locally;
- acquiring proprietary licenses;
- implementing production BackendAdapters;
- release-specific API integration;
- full `describe_effects()` runtime instrumentation;
- production comparator registries;
- rollback/transaction implementation;
- multi-product orchestration execution;
- numerical accuracy/performance validation;
- full backend execution V&V.

These belong to implementation or Adapter-development projects.

### 4. Allowed design-stage smoke evidence

Very small reference or synthetic cases MAY continue to be used to test implementability, for example:

```text
TemperatureField
+ HeatConduction
+ ThermalConductivity
+ one TemperatureBoundaryCondition
+ StationaryAnalysis
```

or a small QRC reaction-product fixture.

Failure of such a smoke case SHALL be classified before any architecture is reopened. Installation/license/runtime unavailability is an external stage constraint, not an Architecture defect.

### 5. Backend validation ownership after freeze

Future backend work SHALL classify findings as:

```text
Architecture defect
Profile defect
Adapter defect
Backend limitation
Reference-model defect
Validation-tooling defect
```

Only evidence classified as Architecture defect may directly trigger reconsideration of this freeze. Profile, Adapter, backend, reference-model, and tooling defects remain in their respective workstreams unless they expose an architecture-level counterexample.

## Next state

The Simulation Ontology project moves from architecture design into **language/schema consolidation and reference-model implementation** using the frozen architecture baseline.

Production-quality BackendAdapter development and backend execution validation should be handled as separate Adapter projects/workstreams. If those projects later produce genuine architecture counterexamples, they return through the ADR process rather than modifying the frozen baseline directly.

## Decision summary

SOL v0.1 design-stage architecture through ADR-0012 is frozen. Architecture/contract completeness is accepted independently of production Adapter readiness and backend runtime availability. Future changes require evidence of an architecture-level defect or contradiction.

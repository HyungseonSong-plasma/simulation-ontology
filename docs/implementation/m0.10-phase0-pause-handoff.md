## Purpose

This handoff records the durable SOL state at the intentional pause point after M0.10 Phase 0. The pause is operational/resource-driven, not a semantic blocker or milestone cancellation.

## Accepted Phase 0 state

The following architecture is accepted:

```text
Public Contract 0.3
  -> canonical run/result semantics

Adapter Protocol 0.3
  -> result-capable adapter interoperability

SimulationRunRecord
  -> canonical operational record
  -> not model-semantic ontology identity

ObservationModel
  -> requested canonical observation meaning

ObservationResult
  -> scientific/numerical result actually produced

Scalar result
  -> inline value + canonical unit

Distributed field result
  -> canonical DatasetManifest
  -> solver-neutral DataReference

Backend-native result artifact
  -> opaque provenance only
```

Public Contract 0.1/0.2 and Adapter Protocol 0.1/0.2 remain frozen in meaning. Old adapters are not silently promoted to the 0.3 result-capable path.

Execution completion does not imply observation production. Every requested observation must receive exactly one terminal outcome: produced result or typed non-production evidence/diagnostic.

## Validator gates preserved for downstream implementation

1. Public Contract 0.3 must not redefine Public Contract 0.2 realization semantics.
2. Adapter Protocol 0.3 must not relabel or auto-promote Adapter Protocol 0.2 adapters.
3. A distributed/field result cannot become canonical solely from a backend-native artifact reference.
4. Every requested observation requires exact terminal coverage independently of the top-level execution outcome.

## Intentional pause and next active team

Under the accepted resource-aware sequencing, SOL pauses after Phase 0 and the MOOSE adapter becomes the primary active team.

```text
SOL M0.10 Phase 0       COMPLETE / PAUSE POINT
        |
        v
MOOSE A0.1              NEXT PRIMARY WORK
        |
```

The MOOSE A0.1 scope must not be retroactively expanded to include Public Contract/Adapter Protocol 0.3. A0.1 should complete its existing Public Contract 0.2 / Adapter Protocol 0.2 thermal realization path:

```text
RealizationSpec
  -> typed MOOSE IR
  -> deterministic `.i`
  -> real MOOSE execution
  -> native artifact capture / adapter-owned V&V
```

The real MOOSE execution/artifact evidence from A0.1 should inform later SOL M0.10 result-contract implementation, especially Phase 1 scalar observations and Phase 2 distributed-field/artifact boundaries.

## SOL resume point

When SOL work resumes, the first eligible Core Phase is #155, **Canonical Observation Result Model**.

Before implementing #155, Operator should re-run normal `init`/state reconstruction and verify:

- current `main` and open PR/issue state;
- whether MOOSE A0.1 completed and what result/artifact evidence it produced;
- whether any new real-adapter evidence contradicts ADR-005;
- whether a new Manager `meeting` is required.

A new meeting is required before implementation if MOOSE evidence exposes a semantic contradiction involving canonical result identity, observation coverage, dataset content identity/normalization, concrete field storage format, or existing 0.1/0.2 compatibility meaning.

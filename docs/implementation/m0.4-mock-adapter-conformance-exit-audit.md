# M0.4 MockAdapter Protocol Conformance Exit Audit

**Status:** APPROVE — merge-gated milestone exit candidate  
**Date:** 2026-08-21  
**Milestone:** M0.4 — MockAdapter Protocol Conformance  
**Parent tracker:** #65  
**Exit gate:** #71

## Purpose

This audit evaluates whether M0.4 has made MockAdapter an executable in-process reference implementation of the published transport-independent Adapter Protocol 0.1 baseline without changing published protocol meaning, introducing transport behavior, or claiming solver-native physical correctness.

The audit is an acceptance review of the M0.4 implementation boundary. It does not publish a new Adapter Protocol version and does not make MockAdapter a real solver adapter.

## Validator verdict

**APPROVE, subject to the final merge gate.**

The Phase 0–5 implementation evidence is internally consistent with the published Adapter Protocol 0.1/Public Contract 0.1 boundary. No unresolved semantic, architecture, Public Contract, Adapter Protocol, roadmap, or compatibility contradiction was identified in this audit.

The remaining milestone gate is mechanical/execution evidence: the exact current Phase 5 PR head must pass the required CI sequence, remain mergeable with no blocking review/conflict, and the milestone-exit PR must be merged through the user-controlled milestone closure gate. M0.4 is not closed merely because this audit says APPROVE.

## Executable conformance matrix

The final M0.4 suite includes dedicated tests for:

- description and dual compatibility;
- accepted and adversarial preflight;
- exact/degraded/unsupported/partial/unavailable execution;
- changed/current-state authoritative rejection;
- dependency-safe alternate and parallel schedules;
- typed ProtocolFailure and side-effect evidence;
- repeated validation and repeated execution state handling;
- ambiguous response-loss safety;
- lifecycle separation;
- opaque provenance and backend-native leakage counterexamples;
- source/dependency guards preventing transport and solver coupling;
- an integrated Phase 5 positive/adversarial operation matrix.

Published M0.3 fixtures are reused as executable evidence where applicable rather than copied into MockAdapter-specific semantic representations.

## Counterexamples that remain rejected

M0.4 does not permit any of the following interpretations:

```text
accepted validate_plan -> durable execute authorization
same execute request -> same execution attempt
no execute response -> no side effect
no execute response -> safe automatic replay
ProtocolFailure -> SOL lifecycle state
execution failed/rejected/unavailable -> ProtocolFailure by definition
canonical plan representation order -> mandatory physical total order
opaque backend reference -> canonical semantic identity
protocol conformance -> backend physical correctness
MockAdapter conformance -> real solver validation
```

## Accepted deferrals

- JSON-RPC / process stdio transport, framing, request IDs, process/session lifecycle, transport errors, reconnect/backoff, and transport replay orchestration remain M0.5.
- Reusable external-adapter conformance runner/tooling remains M0.6.
- Real solver adapters remain separate repositories/projects after reusable Core-side foundations.
- Stable SDK ergonomics remain downstream of the published contract/protocol boundaries.

## Final merge / closure rule

M0.4 may close only when all of the following are true:

1. the Phase 5 PR is green on its exact current head through the complete required CI sequence;
2. no unresolved review, merge conflict, permission, or compatibility gate exists;
3. the Phase 5 milestone-exit PR is merged through the explicit milestone closure gate;
4. merged `main` is verified;
5. #71 and parent #65 are closed as completed and GitHub Milestone #1 is ready to close;
6. Operator `update` synchronizes post-M0.4 documentation before M0.5 implementation begins.

Until those conditions are satisfied, this document is an APPROVE verdict for a **merge-gated milestone exit candidate**, not evidence that M0.4 is already closed.

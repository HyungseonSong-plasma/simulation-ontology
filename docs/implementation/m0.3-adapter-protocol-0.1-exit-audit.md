Status: **APPROVE — merge-gated publication candidate**

Scope: final adversarial review of M0.3 against ADR-002, the accepted Manager review, parent issue #38, Phase 5 issue #44, and the executable Protocol 0.1 schema/fixture/test corpus.

## Counterexample coverage retained from Phases 1–4

The Phase 5 gate intentionally reuses rather than replaces the earlier executable corpus. The combined tests cover:

- Protocol compatible / Public Contract incompatible;
- Public Contract compatible / Protocol incompatible;
- missing compatibility evidence;
- malformed version/support shape;
- target mismatch, missing capability, unsupported action, precondition rejection, and transient unavailability;
- durable preflight-token authority and backend-native preflight leakage;
- changed-plan TOCTOU;
- alternative dependency-preserving order and parallel independent execution;
- dependency-edge violation, action-report coverage errors, state/batch mismatch, and aggregate effect mismatch;
- allowed opaque provenance vs forbidden backend-native semantic identity;
- degraded/unsupported realization evidence without lifecycle conversion;
- repeated validation, repeated execution/current-state rejection, partial prior execution, unresolved prerequisites, and ambiguous response loss;
- raw failure lifecycle/retry-policy conflation.

## Accepted deferrals

These are deliberately **not** M0.3 defects:

- M0.4 — make MockAdapter conform through the published Protocol 0.1 surface and reusable conformance behavior.
- M0.5 — JSON-RPC/stdio transport, framing, request IDs, process lifecycle, transport error mapping, reconnect/backoff, and replay mechanics subject to M0.3's ambiguous-side-effect constraints.
- M0.6 — reusable adapter conformance tooling for external/real adapters.
- Real MOOSE adapter — separate repository/track after the reusable Core-side conformance foundation; experimental spikes may provide feedback without silently mutating Protocol 0.1.
- General dynamic capability/event model — deferred absent new evidence and Manager review.

## Publication rule

Once the Phase 5 PR is merged, Protocol 0.1 is a **published, versioned v0.x interoperability baseline**. Its structural and normative meanings must not be silently redefined. Incompatible feedback requires an explicit new protocol version boundary and migration evidence.

Final exact-head CI evidence is recorded operationally on PR #63 and issue #44 after this audit document is committed; no merge is permitted without that final green evidence.

## Preserved boundaries

1. Adapter Protocol 0.1 and Public Contract 0.1 remain independent published version axes.
2. MockAdapter protocol conformance does not prove solver-native physical or numerical correctness.
3. Existing Rust-only M0.1 helper APIs remain non-normative compatibility/reference helpers.
4. `validate_plan` remains advisory; `execute_plan` remains authoritative.
5. Execute is non-idempotent by default; response absence is not safe replay authority.
6. Protocol failures, preflight states, and execution states are not SOL lifecycle states.
7. Backend-native data and opaque references do not become canonical semantic identity.
8. M0.4 introduces no JSON-RPC, stdio, process/session, reconnect/backoff, network, or solver-runtime dependency.

## Handoff to M0.5

M0.5 carries the unchanged published Adapter Protocol 0.1 operation payloads over JSON-RPC using process standard input/output.

Phase 0 #75 is the next eligible implementation phase. It must fix the transport/semantic ownership boundary and method mapping before envelope or process implementation begins.

M0.5 must preserve these constraints:

- JSON-RPC request IDs are transport correlation only;
- `ProtocolFailure` remains distinct from JSON-RPC transport/protocol errors;
- process/transport outcomes do not become SOL lifecycle states;
- response loss does not authorize blind retry of `execute_plan`;
- in-process and subprocess paths remain semantically equivalent;
- network/gRPC and solver-runtime dependencies remain out of scope.

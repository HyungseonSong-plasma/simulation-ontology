# M0.5 JSON-RPC/stdio transport exit audit

## Purpose

This is the milestone-exit audit for M0.5. It verifies that the generic local subprocess
session preserves the published Adapter Protocol 0.1 semantics already exercised by the
in-process MockAdapter, while process lifecycle, JSON-RPC correlation, stderr, failure
propagation, reconnect, and replay policy remain transport-only concerns.

The audit does not promote a process, session, request ID, CLI profile, or backend-native
identifier into SOL semantic identity.

## Reviewed baseline

- Adapter Protocol 0.1 schemas, fixtures, and failure algebra.
- M0.4 MockAdapter conformance evidence.
- M0.5 Phase 0 JSON-RPC/stdio boundary.
- M0.5 Phase 1 request identity and correlation.
- M0.5 Phase 2 process lifecycle and typed adapter session.
- M0.5 Phase 3 transport/process error propagation.
- M0.5 Phase 4 reconnect, replay, and ambiguous execution safety.
- The integrated Phase 5 subprocess parity matrix.

## Executable conformance matrix

The integrated matrix in
crates/sol-mock-adapter/tests/subprocess_parity_matrix.rs proves:

- every CLI profile has a stable round-trip wire name;
- the default worker remains the exact thermal reference profile;
- describe success and compatibility failure preserve canonical Protocol evidence;
- validate success, negative responses, adversarial requests, and ProtocolFailure values
  are canonically equal across in-process and subprocess paths;
- execute success, negative responses, scheduling variants, prior-state rejections, and
  side-effect-bearing ProtocolFailure values are canonically equal across both paths;
- malformed envelope, exit code/stderr, and execute response loss do not become Protocol
  outcomes; and
- a fresh observer session sees no hidden replay after ambiguous execute response loss.

Earlier Phase 3 and Phase 4 focused tests remain in force and provide the complete
error-kind and operation-specific recovery matrices.

## Rejected counterexamples

The audit explicitly rejects these implications:

- in-process result -> subprocess result without canonical Protocol decoding and comparison;
- process exit -> Adapter Protocol outcome;
- lost execute response -> automatic replay;
- profile name -> semantic identity;
- stderr -> SOL lifecycle state;
- request ID -> semantic operation identity;
- new process -> continuation of the prior session;
- transport/process error -> ProtocolFailure; and
- opaque backend reference -> backend-native semantic authority.

## Scope and dependency findings

The Phase 5 profile switch is a deterministic test-control surface on the local worker.
It selects existing MockAdapter states before bootstrap. The profile value is absent from
Adapter Protocol payloads and does not grant retry, replay, lifecycle, or identity
authority.

No network runtime, remote service, solver SDK, or backend-native dependency is added.
The reference path remains local, offline, deterministic, and solver-independent.

## Deferred work

The following remain outside M0.5 and do not weaken this verdict:

- packaging the reference adapter/transport as external conformance tooling;
- network or distributed transports such as HTTP, gRPC, queues, or sockets;
- real solver process integration and backend-specific orchestration;
- durable deduplication, resume tokens, or retry authority; and
- broader semantic lifecycle work owned by later milestones.

These are M0.6-or-later concerns and must not be inferred from the local stdio reference.

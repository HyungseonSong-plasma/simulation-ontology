## Result

M0.6 provides reusable Core-side tooling that lets external adapter projects demonstrate conformance with published Adapter Protocol 0.1 / Public Contract 0.1 behavior through the accepted process transport boundary without linking solver runtimes into Core or claiming solver-native physical/numerical correctness.

The completed conformance-tooling behavior includes:

- a reusable conformance result algebra with `Conformant`, `NonConformant`, and `NotEstablished` aggregate outcomes;
- explicit separation of adapter non-conformance from fixture/invocation/transport/result-decoding/runner harness failures;
- external adapter invocation through the published JSON-RPC/stdin-stdout process transport;
- dual Adapter Protocol/Public Contract compatibility evidence before operation-level conformance;
- published positive Protocol/Public Contract fixture execution through canonical DTO parsers;
- a 23-case adversarial matrix covering compatibility, target/capability/preflight negatives, execution states, ProtocolFailure behavior, scheduling, prior execution, transport loss, aggregate effects, and provenance identity;
- request-relative detection of parsable dependency-schedule, aggregate-effect, and provenance-identity violations as `NonConformant`;
- ambiguous execute response loss preserved as harness/transport evidence with `NotEstablished`, without automatic replay authority;
- a solver-independent Rust/stdin-stdout adapter-authoring skeleton and guide;
- a standalone nested Cargo workspace demonstrating external-project-style conformance consumption without linking the reference adapter implementation or solver/vendor runtimes;
- reusable published fixtures copied to an external CI temporary path rather than requiring a Core-relative runtime location;
- deterministic machine-readable CI evidence generated twice and checked byte-for-byte; and
- an explicit provisional boundary around exact conformance CLI spelling, exit-code behavior, environment-variable names, profile controls, and serialized report shape.

## Preserved boundaries

1. Adapter Protocol 0.1 and Public Contract 0.1 meanings and version axes remain unchanged.
2. Conformance is interoperability evidence, not SOL lifecycle/evaluation classification.
3. Conformance does not assess backend physical or numerical correctness.
4. `ProtocolFailure`, valid negative Protocol responses, transport/harness failures, and lifecycle state remain distinct.
5. `validate_plan` remains advisory and side-effect free; `execute_plan` remains authoritative for current-state checks.
6. Lost execute responses do not authorize automatic replay and conservatively preserve possible side effects.
7. Backend-native identifiers may appear only as opaque provenance/evidence and cannot define canonical semantic identity.
8. Exact conformance CLI spelling, serialized report shape, environment-variable names, profile controls, and exit-code behavior remain provisional until an explicit public-interface decision stabilizes them.
9. No MOOSE, COMSOL, Ansys, Zapdos, CRANE, or other solver runtime dependency is added to Core solely for conformance tooling.
10. Real solver adapters remain independent repositories/projects with their own backend-native V&V responsibility.

## Handoff after M0.6

With the reusable conformance foundation accepted, the roadmap permits two successor tracks to proceed in parallel:

```text
SDK track                    Real-adapter track
TypeScript / Python          sol-adapter-moose
                             separate repository
```

The SDK track must consume the canonical Public Contract / Adapter Protocol rather than freezing incidental Rust internals. The MOOSE adapter must advertise explicit supported Adapter Protocol and Public Contract ranges and must keep solver-native mapping correctness, regression testing, and physical/numerical V&V outside Core conformance semantics.

Choosing concrete scope, milestone decomposition, or compatibility commitments for either successor track is a new planning decision and belongs to Manager `meeting` before implementation begins.

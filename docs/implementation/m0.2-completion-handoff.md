## Public Contract 0.1 delivered surface

M0.2 establishes:

- independent `public_contract_version: "0.1"` handling and canonical JSON rules;
- model-facing DTOs including first-class `SpatialScope`;
- `ValidationReport` and stable machine-consumable diagnostics;
- mapping claims, DAG-based mapping plans, backend target requirements, realization effects, and evaluation results;
- preservation of the M0.1 lifecycle mapping `PASS / FAIL / BLOCKED / INDETERMINATE`;
- Draft 2020-12 JSON Schemas under `schemas/public-contract/0.1/`;
- Thermal positive goldens plus structural and semantic counterexamples;
- executable compatibility regression coverage for compatible, incompatible, and unknown evidence;
- the `sol_public_contract` Rust facade without making Rust crate/layout details normative across languages;
- CLI `--json` paths that emit canonical Public Contract payloads while preserving separate human-readable output.

## Boundary preserved at M0.2 exit

M0.2 does **not** define:

- Adapter Protocol operations;
- JSON-RPC envelopes or request IDs;
- stdio/process lifecycle;
- transport retry/reconnection/replay semantics;
- adapter execution idempotency guarantees;
- backend-native object identity as canonical semantics;
- language-specific SDK semantics ahead of the Public Contract.

These exclusions are intentional and preserve the handoff to later milestones.

## MOOSE adapter timing

The real MOOSE adapter remains an external-repository track. M0.3 may support an experimental repository/spike after the protocol baseline exists, but official reference-adapter development begins only after reusable Core-side protocol conformance tooling is available at M0.6. MOOSE feedback must validate the protocol rather than silently redefine Public Contract or Protocol semantics.

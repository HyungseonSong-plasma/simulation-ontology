## Outcome

M0.8 resolves the real-adapter expressiveness gap raised in #110 by publishing an explicit solver-independent realization boundary without changing Public Contract 0.1 or Adapter Protocol 0.1 semantics.

The accepted architecture is:

```text
MappingPlan
  = action identity + dependency DAG

RealizationSpec
  = canonical solver-independent realization semantics

Adapter Protocol 0.2 request
  = target + plan + realization_spec
```

MappingPlan action-ID spelling and opaque PlanAction extensions remain non-semantic. Backend-native object identity remains outside canonical SOL meaning.

## Version boundary

```text
Public Contract 0.1      frozen / unchanged
Adapter Protocol 0.1    frozen / unchanged

Public Contract 0.2      explicit RealizationSpec boundary
Adapter Protocol 0.2    explicit realization transport boundary
```

Realization 0.2 compatibility requires both Adapter Protocol 0.2 and Public Contract 0.2 compatibility. Adapter implementation/package version implies neither.

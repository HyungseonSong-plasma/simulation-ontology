## Published invariants

1. Public Contract and Adapter Protocol remain independent version axes.
2. Interoperability requires compatible Protocol and Public Contract evidence.
3. Protocol responsibilities are not one-to-one Rust traits or transport methods.
4. `validate_plan` is advisory; `execute_plan` is authoritative.
5. Canonical MappingPlan order is not mandatory physical backend order.
6. `execute_plan` is non-idempotent by default; response absence is not replay permission.
7. Protocol failures and execution/preflight states are not SOL lifecycle states.
8. Backend-native object models cannot become canonical semantic identity.
9. Protocol 0.1 semantics cannot be silently redefined after publication.
10. JSON-RPC/stdio mechanics remain outside Adapter Protocol 0.1 and belong to M0.5.
